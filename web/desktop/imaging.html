Image and file backups, schedules, clients, and restores are all managed in the UrBackup UI, not here. First thing after install: UrBackup Settings → Backup storage path → point it at a storage pool (e.g. /srv/nas/tank/urbackup), never the root filesystem.

Restoring a machine

  1. Download the UrBackup Restore CD ISO from urbackup.org and write it to a USB stick.
  2. Boot the target machine from the stick; it finds this server on the LAN.
  3. Pick the image backup to restore. Full-disk images restore bootable systems.

Install from the box (package installs are a root-CLI operation, kept outside the API on purpose):

sudo forgeos-imaging install

Pinned to a verified upstream release; upgrades are manual (not covered by unattended-upgrades) — rerun install after a version bump. Then refresh this page and set the backup storage path in UrBackup’s Settings to a storage pool.

How it works

  1. The UrBackup server runs here and stores backups on your NAS.
  2. Install the UrBackup client on each Windows/Linux/Mac machine; LAN clients are discovered automatically.
  3. Clients get scheduled file backups and full image backups (Windows: live via VSS).
  4. A dead machine is brought back with the restore boot stick — no OS reinstall.

This replaces the never-implemented FOG integration — UrBackup covers capture, scheduling, and restore with a maintained upstream.
